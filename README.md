# moxule-components

Component library for m-ox to use.

## Scripts

- `npm run dev`: Build in watch mode
- `npm run demo`: Run Vite sample page locally
- `npm run demo:build`: Build Vite sample page
- `npm run demo:preview`: Preview built Vite sample page
- `npm run build`: Build ESM and CJS bundles with type declarations
- `npm run typecheck`: Run TypeScript checks
- `npm test`: Run tests once

## Demo routing and pages

The demo uses React Router with `BrowserRouter` in `src/demo/main.tsx`.
`App` composes `DemoProvider` and `NavRouter`. Dashboard is the home page at `/`.
Older `/dashboard` URLs redirect home, preserving query strings and section
anchors; unknown URLs show a page with a link back to Dashboard.

`NavRouter.tsx` owns route definitions and their `handle.breadcrumb` labels.
It supplies the matching breadcrumb trail to `AppLayout`, which displays it
above the page content alongside the shared navbar and natural footer.
Add new page routes and their breadcrumb labels in `NavRouter`.
The trail follows matched route ancestry: Dashboard shows a single current-page
marker, and nested pages add their actual parent steps.

`pages/Dashboard/DashboardPage.tsx` composes the font preview, theme preview,
and General Components sections. Each section and control example lives in
its own file. Shared theme, mode, font, size, and density preferences live in
`DemoProvider` and survive page navigation; interactive example state stays
with its example. Footer links navigate to actual dashboard sections.


## First component

`Button` is exported from the package root:

```tsx
import { Button } from "moxule-components";
import "moxule-components/styles.css";

export function Example() {
  return <Button variant="primary">Click me</Button>;
}
```

## Theming

Import `moxule-components/styles.css` once in your app entry point. Default component styles, theme palettes, and font variants are provided by CSS classes and data attributes. Explicit `sx`/`style` overrides and `customTokens` remain inline so they take precedence. Theme CSS is generated from the TypeScript token definitions by `npm run styles:generate`, and is regenerated by the library and demo build commands.

The Vite demo also regenerates theme CSS when palette, CSS-variable mapping, or font definitions change, so the preview updates without restarting the server.

Use `ThemeProvider` to control color mode (`light` or `dark`) and theme flavor (`primary`, `secondary`, `tertiary`, `blue`, `red`, `green`, `purple`, or `pink`).

Font styling presets are also available:

- `fontStyle="clear"` -> Cantarell display font
- `fontStyle="playful"` -> DynaPuff display font
- `fontStyle="stark"` -> Martel display font
- `fontStyle="bizarre"` -> Loved by the King display font

Body text defaults to Gudea. Header, toolbar logo, and footer use the display font.

Typography uses the CSS variable `--mx-font-scale` (default `1`). The demo's Size dropdown sets Small to `0.875`, Medium to `1`, and Large to `1.125`, scaling headings, body text, controls, labels, and footer text together. This leaves spacing under the separate density setting and preserves browser font preferences.

Many components also accept semantic `color` values (for example `primary`, `secondary`, `tertiary`, `blue`, `red`, `green`, `purple`, `pink`) so you can apply a specific theme palette per component.

```tsx
import { Button, ThemeProvider } from "moxule-components";

export function Example() {
  return (
    <ThemeProvider mode="dark" theme="secondary">
      <Button variant="primary">Primary action</Button>
      <Button variant="secondary">Secondary action</Button>
      <Button variant="ghost">Ghost action</Button>
    </ThemeProvider>
  );
}
```

You can also override individual tokens for a custom brand theme:

```tsx
<ThemeProvider
  mode="light"
  theme="primary"
  customTokens={{
    buttonPrimaryBg: "#0057ff",
    buttonPrimaryText: "#ffffff",
    fontDisplay: '"Inter", sans-serif',
    fontBody: '"Source Sans 3", sans-serif'
  }}
>
  <Button>Custom brand button</Button>
</ThemeProvider>
```

## Footer

Use `Footer` for bottom page navigation/actions with either centered content or evenly split sections.

- `position="natural"` keeps footer in normal document flow (good for long pages).
- `position="static"` fixes footer to the viewport bottom.

```tsx
import { Footer, Link } from "moxule-components";

export function FooterExamples() {
  return (
    <>
      <Footer layout="centered" position="static">
        <Link href="#about" color="inherit">About</Link>
        <Link href="#terms" color="inherit">Terms</Link>
        <Link href="#privacy" color="inherit">Privacy</Link>
      </Footer>

      <Footer layout="split" position="natural">
        <span>Column one</span>
        <span>Column two</span>
        <span>Column three</span>
      </Footer>
    </>
  );
}
```

## Toggle

Use `Toggle` as a reusable switch control with a classic sliding bubble.

```tsx
import { useState } from "react";
import { Toggle } from "moxule-components";

function SoundSwitch() {
  const [checked, setChecked] = useState(false);

  return (
    <Toggle
      checked={checked}
      onCheckedChange={setChecked}
      label="Enable sound"
    />
  );
}
```

Visible toggle labels are clickable and supply the accessible name. The demo's Toggle card includes an independent sound switch and a disabled example.

## ThemeToggle

Use `ThemeToggle` in a navbar or toolbar for a reusable light/dark switch with sun and moon icons. Light mode uses a warm amber track, and dark mode uses a deep navy track with a pale moon thumb. These colors stay recognizable across theme palettes. It reads the current mode from `ThemeProvider` and sends the next mode to `onModeChange`.

```tsx
import { useState } from "react";
import { ThemeProvider, ThemeToggle, Toolbar, type ThemeMode } from "moxule-components";

function App() {
  const [mode, setMode] = useState<ThemeMode>("light");
  return (
    <ThemeProvider mode={mode}>
      <Toolbar left={<strong>App</strong>} right={<ThemeToggle onModeChange={setMode} />} />
    </ThemeProvider>
  );
}
```

Pass `mode` explicitly when using it outside a provider. `label`, `labelPosition`, `ariaLabel`, `disabled`, native button props, and class/style overrides are supported. The checked state represents dark mode. The parent owns mode state, and the default focus outline inherits the surrounding text color for visibility on navbar backgrounds.

## Section

Use `Section` to group a heading, description, and related content. It renders the semantic section, `Header`, and `Text`, and automatically connects their accessible labels and descriptions.

```tsx
import { Button, Section } from "moxule-components";

<Section
  title="Account settings"
  description="Manage your account preferences."
  headingLevel="h2"
>
  <Button>Save preferences</Button>
</Section>
```

`title` and `description` are optional React content. `headingLevel` defaults to `h2`; select the level that fits the surrounding page hierarchy. `headingProps` and `descriptionProps` customize their typography, IDs, and classes. Native section attributes, a section `ref`, and `sx`/`style` overrides are supported. Default styles inherit the current theme and font scale; `--mx-section-gap` controls the default `0.75rem` gap.

## Card

Use `Card` for reusable surface items tied to the theme. Light themes use clean white cards against the tinted page background; dark themes retain their dark surfaces. Cards have no borders, decorative outlines, or shadows. `appearance="none"` and the legacy `appearance="outline"` provide a transparent container.

```tsx
import { Card, Header, Text } from "moxule-components";

export function ExampleCard() {
  return (
    <Card>
      <Header variant="h4">Card title</Header>
      <Text variant="sm" sx={{ marginTop: "0.5rem" }}>
        Card body content.
      </Text>
    </Card>
  );
}
```

## Link

`Link` renders a themed anchor with an underline and a rounded, visible focus outline. Use `color="inherit"` on footer or toolbar backgrounds.

```tsx
import { Link } from "moxule-components";
import { Link as RouterLink, NavLink } from "react-router-dom";

<Link href="https://example.com">Documentation</Link>

<Link asChild>
  <RouterLink to="/settings">Settings</RouterLink>
</Link>

<Link asChild>
  <NavLink to="/reports" className={({ isActive }) => isActive ? "active" : undefined}>
    Reports
  </NavLink>
</Link>
```

`asChild` applies styling to one child link without adding another anchor. Put routing props such as `to`, `state`, and `replace` on the child and render it within your router. React Router is not a runtime dependency of this library. The wrapper preserves child refs, event handlers, and [NavLink render callbacks](https://reactrouter.com/api/components/NavLink) for class names, styles, and content.

Native anchor props, `class`/`className`, `sx`/`style`, and an anchor `ref` are supported. With `asChild`, the child must forward those props to its anchor. Classes are combined; child props and styles take precedence. Child handlers run first, and preventing default skips the corresponding wrapper handler. A wrapper handler can also prevent navigation.

## Image

Use `Image` for consistent image rendering with library prop conventions.

If loading fails or no source is provided, `Image` renders a circular span with the uppercased first character of its trimmed `alt` text. The fallback retains the full accessible name, classes, explicit dimensions, and style overrides; decorative images remain hidden from assistive technology. `onError` still receives the original image error event. Changing `src`, `srcSet`, or `sizes` retries loading automatically, so consuming components do not need their own failure state.

```tsx
import { Image } from "moxule-components";

export function Logo() {
  return (
    <Image
      src="/favicon.png"
      alt="Brand logo"
      width={32}
      height={32}
      sx={{ borderRadius: "999px", objectFit: "cover" }}
    />
  );
}
```

## Dropdown

Use `Dropdown` for selecting from a list of options. It has a borderless fill and a visible focus ring when focused.

Dropdowns inside filled cards use a theme-colored inset tint in light mode, with a stronger tint on hover. Dark mode uses a darker inset fill. The overlay only changes the background, preserving the text, caret, and focus ring colors.

```tsx
import { Dropdown } from "moxule-components";

const options = [
  { label: "Blue", value: "blue" },
  { label: "Primary", value: "primary" }
];

export function ThemePicker() {
  const [theme, setTheme] = useState("blue");

  return (
    <>
      <label htmlFor="theme-picker">Theme</label>
      <Dropdown
        id="theme-picker"
        options={options}
        value={theme}
        onChange={setTheme}
      />
    </>
  );
}
```

## RadioGroup and CheckboxGroup

Use `RadioGroup` for a list of mutually exclusive options. It renders the fieldset, legend, optional description, and labelled native radio inputs. Pass `options` as `{ label, value, disabled? }` objects with unique values. Use `value` and `onChange(value)` for controlled selection, or `defaultValue` for native uncontrolled selection and form reset. A shared `name` is generated if omitted; supply it explicitly for form submission. `disabled` disables the group, and `required` enables native validation. Fieldset attributes, a fieldset `ref`, and `sx`/`style` overrides are supported.

`Radio` remains available for custom layouts. `Radio` and `Checkbox` accept a required visible `label`, native input props, and an input `ref`.

Use `CheckboxGroup` for multiple selections with component-owned spacing. It owns the fieldset, legend, description, and option list, with a default `0.75rem` vertical gap. Set `--mx-checkbox-group-gap` in CSS to customize spacing. Its `value`/`defaultValue` are arrays, and `onChange` receives the selected values. Options accept `{ label, value, disabled?, required? }`; `required` applies to an individual checkbox.

```tsx
import { useState } from "react";
import { CheckboxGroup, RadioGroup } from "moxule-components";

export function Preferences() {
  const [density, setDensity] = useState("comfortable");
  const [notifications, setNotifications] = useState<string[]>([]);

  return (
    <>
      <RadioGroup
        name="density"
        legend="Display density"
        description="Choose the preview spacing."
        options={[
          { label: "Comfortable", value: "comfortable" },
          { label: "Compact", value: "compact" }
        ]}
        value={density}
        onChange={setDensity}
      />
      <CheckboxGroup
        legend="Notifications"
        name="notifications"
        options={[
          { label: "Email", value: "email" },
          { label: "SMS", value: "sms" }
        ]}
        value={notifications}
        onChange={setNotifications}
      />
    </>
  );
}
```

## Accessible controls

The demo's General Components section follows Theme Color Preview and includes interactive examples of `Button`, `Dropdown`, `RadioGroup`, `Checkbox`, and `Toggle`. The Comfortable and Compact radio options change preview spacing and card padding. Controls inherit theme colors and fonts, with visible focus outlines and native keyboard behavior. `ThemeProvider` sets the browser color scheme for native controls. The select uses an inset SVG caret with `currentColor` so it can follow forced colors, and radio and checkbox inputs retain their native appearances.

Provide a meaningful button name and a visible `<label htmlFor="...">` for each `Dropdown`. `RadioGroup` supplies a shared `name`, a `<fieldset>`, and a `<legend>`, following W3C guidance for [labels](https://www.w3.org/WAI/tutorials/forms/labels/) and [grouping controls](https://www.w3.org/WAI/tutorials/forms/grouping/). Do not put links or other interactive elements inside radio or checkbox labels.

Tests cover accessible names, descriptions, focus, disabled behavior, selection, form validation and submission, and default theme text contrast of at least 4.5:1. Custom token overrides and style overrides need their own contrast checks. These components support the [Section 508 WCAG AA requirements](https://www.section508.gov/test/websites/); full application conformance also requires manual keyboard, screen reader, and forced colors testing.

Buttons use their theme's primary, secondary, or ghost hover colors, including explicit per-button theme colors. Dropdowns gain a soft themed fill on hover, and radio and checkbox hit areas gain a matching tint. Disabled controls keep their resting appearance, focus rings remain visible, and the transitions respect reduced-motion preferences.

## Modal

`Modal` is a centered, controlled dialog with the same keyboard, focus, scroll
locking, and dismissal behavior as Drawer. It has a flat themed surface and a
delicate 240ms fade with a small vertical movement, respecting reduced motion.

```tsx
<Modal
  title="Confirm changes"
  description="Review before continuing."
  open={open}
  onOpenChange={setOpen}
  size="md"
  footer={<Button onClick={() => setOpen(false)}>Continue</Button>}
>
  <Text>Your changes are ready.</Text>
</Modal>
```

Sizes are `sm` (24rem), `md` (32rem), and `lg` (44rem), constrained to the viewport.
`footer` accepts action content. `closeOnEscape`, `closeOnBackdrop`, `closeLabel`,
`initialFocusRef`, `onDismiss`, native dialog props, and style overrides are supported.
Keep the component mounted while setting `open={false}` so its exit can finish.

Cards and Modal use tighter top-left/bottom-right corners and softer opposite
corners. Customize the default `4px 18px 4px 18px` with `--mx-panel-radius`.
The Modal example card follows Drawer in General Components.

## Drawer and MenuButton

`Drawer` is a controlled modal panel with `side="left"` or `side="right"`
(default right). It uses the native dialog top layer to contain focus and make
the background inactive. It inherits theme colors and fonts, with a flat,
borderless surface and a soft 240ms slide/fade.

```tsx
import { useId, useState } from "react";
import { Drawer, MenuButton } from "moxule-components";

function Navigation() {
  const [open, setOpen] = useState(false);
  const id = useId();
  return <>
    <MenuButton open={open} aria-controls={id} onClick={() => setOpen(true)} />
    <Drawer id={id} title="Menu" side="left" open={open} onOpenChange={setOpen}>
      Navigation content
    </Drawer>
  </>;
}
```

`title` supplies the accessible name; optional `description` is automatically
associated. The close button, Escape, and backdrop request closing through
`onOpenChange(false)`. Set `closeOnEscape` or `closeOnBackdrop` to false to disable
those interactions. Use `initialFocusRef` for an alternate initial focus target
and `closeLabel` to name the close button. `onDismiss` runs after closing finishes.

Keep the Drawer mounted while changing `open`. It locks page scrolling until
the exit finishes, restores focus to the opener, cancels pending exits when
reopened, and cleans up on unmount. Reduced motion skips the animation.
Set `--mx-drawer-width` in CSS to customize the default 22rem width.

The demo's menu button sits in the navbar beside the light/dark toggle. Its
left drawer links to Dashboard and its sections. The Drawer card in General
Components lets you try either side.

## Nudges and notifications

Wrap the app with `NudgeProvider` inside `ThemeProvider`, then call `useNudges()`
from any descendant. Nudges stack in the bottom-right corner by default and
share Banner's status colors, custom accent support, and flat surface.

```tsx
import { NudgeProvider, ThemeProvider, useNudges, Button } from "moxule-components";

function SaveExample() {
  const { nudge } = useNudges();
  return <Button onClick={() => nudge({ message: "Saved!", variant: "success" })}>Save</Button>;
}

<ThemeProvider>
  <NudgeProvider position="bottom-right">
    <SaveExample />
  </NudgeProvider>
</ThemeProvider>
```

Variants are `success`, `warning`, `error`, and `neutral`; `color` accepts any CSS
accent color. `nudge("Message")` is a neutral shortcut. Each call returns an ID
for `dismiss(id)`; `dismissAll()` clears the stack with the same gentle animation.
`Nudge` is also exported for standalone use.

Non-error nudges close after six seconds by default. Errors stay until closed;
set `duration: 0` to keep any message visible, or supply a duration in milliseconds.
The provider's `duration` changes the default for non-errors. Timers pause on
hover and keyboard focus. Each nudge has a close X, announces its message without
taking focus, and respects reduced-motion preferences. `onDismiss` runs after the
240ms exit animation. Pending timers are cancelled on unmount.

The provider supports all four corner positions, inherits theme/font changes,
and scrolls for long queues. The demo's Notifications card follows Toggle and
lets you trigger each status, the current theme color, and custom-color examples.

## Breadcrumbs

`Breadcrumbs` renders an accessible ordered navigation trail using themed
`Link` components. Pass `items` from root to current page. The last item is
plain text with `aria-current="page"`. Parent pages have outlined circles and the
current page has a filled circle, with small lightning bolts between steps.
Markers and separators use the theme accent and are decorative. Empty trails
render nothing. Customize the navigation name with `aria-label` and the
separator with `separator`.

```tsx
<Breadcrumbs items={[
  { label: "Home", href: "/" },
  { label: "Dashboard" }
]} />
```

For React Router, supply `renderLink`. It is only called for ancestor items
with an `href`, and its returned link receives the library's styling via
`Link asChild`. React Router remains an optional integration for the library.

```tsx
import { Link as RouterLink } from "react-router-dom";
import { Breadcrumbs } from "moxule-components";

<Breadcrumbs
  items={[{ label: "Home", href: "/" }, { label: "Dashboard" }]}
  renderLink={(item) => <RouterLink to={item.href!}>{item.label}</RouterLink>}
/>
```

The demo builds these items from route metadata and places Breadcrumbs at the
top of the shared app layout, so individual pages don't repeat the trail.

## Banner

`Banner` displays a `message` with a thick left color strip and a themed card surface.
Choose `success`, `warning`, `error`, or `neutral` (default), or set a custom accent
with `color`. The banner and optional close button have no decorative borders or shadows.

```tsx
<Banner variant="success" message="Your changes have been saved." />
<Banner color="#5f4a89" message="A custom notice." dismissible onDismiss={() => console.log("Dismissed")} />
```

`dismissible` adds a keyboard-accessible close X on the right. Closing gently fades
and collapses the banner over 240ms, then calls `onDismiss`. Dismissal is immediate
when the user prefers reduced motion.
Use `closeLabel` to customize its accessible name. Remount the component to show it
again after dismissal. The default role is `alert` for errors and `status` otherwise;
override `role` for static informational content when announcements aren't needed.
Native div props, a ref, and `sx`/`style` overrides are supported.

## PageShell

Use `PageShell` for full-page structure with toolbar/content/footer. It reserves no footer space by default; set `footerOffset` only when using a fixed footer. PageShell and Layout share a background derived by shifting the primary color's hue by -30 degrees, then applying fixed off-white lightness in light mode or subtle charcoal lightness in dark mode. Purple gets a pale blue backdrop. Hex `customTokens.buttonPrimaryBg` overrides also derive the background automatically unless `customTokens.pageShellBg` is supplied explicitly.

```tsx
import { Footer, Layout, PageShell, Toolbar } from "moxule-components";

export function ExamplePage() {
  return (
    <PageShell>
      <Toolbar left={<div>Brand</div>} />
      <Layout margin="lg" contentWidth="md" style={{ flex: 1 }}>
        Main content
      </Layout>
      <Footer layout="centered" position="natural">
        Footer links
      </Footer>
    </PageShell>
  );
}
```
